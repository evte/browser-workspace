# 功能、权限与运行边界

[返回 README](../README.md) · [部署指南](DEPLOYMENT.md) · [桌面打包](PACKAGING.md)

## 当前能力

- 邮箱和密码注册登录，持久会话、退出撤销，首次注册由原管理密码保护并认领旧数据。
- 创建和切换团队，所有者／管理员／成员三级权限；邀请链接绑定邮箱、7 天过期、一次使用并可撤销。
- 单个或批量分配环境给团队成员。普通成员只能查看、操作分配给自己的环境；撤销分配或移除成员会断开远程访问。
- 为环境设置标签和备注，支持标签筛选及名称、标签、备注搜索。
- 为环境保存 2FA 密钥，列表显示当前验证码、剩余秒数和倒计时进度条，支持点击复制。
- 创建、启动、停止和删除独立的浏览器环境。
- 紧凑表格、名称/编号/代理搜索、状态筛选和 25/50/100 条分页。
- 每个环境选择浏览器内核；服务器缺少时自动下载、校验并安装，界面显示进度，下载失败不会换成其他内核启动。
- 指纹内核使用固定设备种子，可配置系统、语言、时区、逻辑处理器数量和画面尺寸；UA 和 Client Hints 由所选内核生成。
- 批量导入 HTTP、HTTPS、SOCKS4、SOCKS5 代理，支持格式选择、凭据、去重和逐行错误提示。
- 为指定环境绑定代理。运行中需先停止再换绑。绑定的代理失效后自动断开该环境全部连接并停止浏览器，需手动重启。
- 新建环境时可直接填写一条代理，自动保存到当前团队的代理列表并绑定；相同代理自动复用。
- 目标网站的 Cookie 和浏览器环境数据保存在服务器的 `browser_data` Docker 卷，重启容器后保留。
- 通过 noVNC 在网页内操作服务端浏览器。启动中的环境允许多个管理界面连接到同一个桌面。

支持系统原生 Chromium 和开源指纹 Chromium，但不等同于 AdsPower 的完整指纹能力，也不能保证各网站不会关联账号。团队权限在 API 和远程桌面连接上检查；每个环境使用独立 Linux UID、私有数据目录、X11 认证凭据和网络命名空间。所有环境仍共享容器内核，Chromium 当前使用 `--no-sandbox`，尚未达到用于不可信租户的独立容器或虚拟机隔离强度。

## 团队与环境分配

顶部可创建和切换团队；环境、代理和分配记录按团队隔离。账号可属于多个团队，在某个团队是管理员不意味着拥有其他团队的权限。

| 角色 | 权限 |
| --- | --- |
| 团队所有者 | 管理全部团队环境、代理、分配和邀请；设置管理员，移除成员；不能移除或降级所有者本人 |
| 管理员 | 管理全部团队环境、代理、分配；邀请和移除普通成员；不能提权或管理其他管理员 |
| 普通成员 | 查看和启动、停止、连接已分配的环境；编辑这些环境的标签和备注 |

在「团队成员」填写邀请邮箱和角色后生成邀请链接，复制并自行发给对方。对方用该邮箱注册或登录，点击接受邀请加入团队。链接只完整显示一次；7 天内可使用一次，重发会撤销该邮箱的旧待用链接，也可手动撤销。当前不发送邮件、不验证邮箱所有权，也没有密码重置邮件服务；加入团队必须同时持有匹配邮箱的账号和有效邀请链接。

管理员可在环境配置里选择成员，也可勾选多行后点击「分配环境」。分配会替换所选环境的成员名单，选空名单则取消所有普通成员的访问；管理员始终可以管理团队环境。环境可以分给多个成员，远程桌面是同一浏览器会话。取消权限后，已打开的远程连接会被关闭，新的输入会重新验权；尚在下载内核的无权启动任务也会取消。

每个环境最多 20 个标签，每个标签最多 32 个字符，备注最多 2000 字符。普通成员可以编辑所分配环境的标签和备注，不可以更改代理、内核、设备指纹或分配权限。

## 环境 2FA 验证码

在「新建环境」或环境行「配置」中填写 2FA 密钥。支持 Base32 密钥（可带空格）和 `otpauth://totp/…` 链接。普通密钥默认生成 6 位验证码，每 30 秒更新；链接可指定 SHA1、SHA256 或 SHA512，6 位或 8 位验证码，以及 15–120 秒周期。算法依据 [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238)。这用于保存目标账号已有的验证器密钥，不会替目标网站开启两步验证，也不是管理平台自身的登录二次验证。

列表的「2FA」列显示当前验证码、剩余时间和进度条，点击验证码可复制。验证码在服务端生成，页面按服务器时间倒计时；到期、离线或访问权限失效后不会继续显示旧码。服务器时间必须准确，建议启用系统自动校时。

团队所有者和管理员可设置、更换或移除环境密钥，普通成员只能查看已分配环境的验证码。编辑时不回显原密钥，留空保持不变，勾选「移除 2FA」才清除；运行中的环境也可修改 2FA。

密钥使用 Fernet 加密后写入服务器数据库，接口只返回验证码和是否已配置，不返回原始密钥。加密主密钥保存在持久化卷的 `/data/totp.key`，权限为 600。备份必须同时包含数据库和该文件，并加密保管整个备份；丢失主密钥后无法恢复已有 2FA 密钥。网页不把密钥保存到本地存储，复制验证码会将该次验证码写入访问设备的剪贴板。

账号密码以独立随机盐的 scrypt 保存（容器默认 `N=2^17,r=8,p=1`）；缺少 scrypt 的本地 Python 使用 PBKDF2-HMAC-SHA256 600000 次。参数依据 [OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。会话及邀请仅存令牌摘要，账号登录有效期 24 小时，退出立即撤销该会话。邀请和登录接口有频率限制。

## 数据与限制

- 持久化卷中包含网站登录凭据。备份时应在停止环境后备份整个 Docker 卷，并加密保管。不要执行 `docker compose down -v`，否则会删除该卷。
- 浏览器的独立 HOME 目录也位于环境持久化目录内。远程画面、输入和可能使用的剪贴板会经过访问设备。
- 如果服务器需要从公网直接访问，先配置 HTTPS 和合适的访问控制，并评估会话和服务的安全性。此原型尚未完成生产级安全加固。
- 应用只支持单个服务进程，重启服务会结束运行中的浏览器进程。环境文件、账号、团队及未过期管理会话保留。内核下载在后台进行；浏览器初始化阶段当前串行处理，同时启动多个环境时需要排队。
- 实际资源消耗取决于网页和并发环境数量，请在服务器上测试后确定容量。


## 批量代理与绑定

新建环境的「访问网络」支持服务器直连、选择已有代理和直接填写代理。选择「直接填写代理」后，指定协议和地址格式，粘贴一条代理即可。点击「创建环境」会同时创建代理和环境并建立绑定，不必提前到代理管理导入。格式错误或环境创建失败时，整次操作回滚，不会留下孤立代理。

当前团队中协议、主机、端口、用户名和密码都相同的代理会直接复用；不同凭据或不同团队会保存为独立记录。创建时只校验地址格式，连接可用性在启动环境时检查，断网保护规则不变。

点击「代理管理 → 批量导入」，选择协议和格式，每行一条。每次最多 1000 条，文件需为 UTF-8、最大 1 MB。含错误行时整批不导入，按行号修正后重试。完全相同的代理会跳过。同一地址换凭据会新增记录，已有环境的绑定保持原配置。

支持以下格式，示例中的域名用于说明，需替换成可用代理。

```text
proxy.example.com:8080
proxy.example.com:8080:username:password
username:password@proxy.example.com:8080
http://username:password@proxy.example.com:8080
```

IPv6 主机需加方括号，例如 `[2001:db8::1]:1080`。URL 格式的凭据特殊字符应使用百分号编码，URL 协议必须与所选协议一致。HTTPS 表示客户端到代理之间使用 TLS，严格校验证书。SOCKS4 使用 SOCKS4a 远程解析域名，仅支持用户标识，没有密码认证。需要密码的 SOCKS 代理请选择 SOCKS5。

导入成功后，在新建环境或环境行「配置」中选择。选择「服务器网络（直连）」即明确解除代理。已绑定环境不会因为代理失败自动改成直连。代理密码仅保存在服务端数据库，列表和错误响应不返回密码；数据库当前为明文凭据，服务端备份应加密保管。

## 内核与设备配置

新建环境默认选择当前服务器架构的指纹内核，旧环境保留系统 Chromium，避免升级时自动改变原有身份。可在停止环境后点击「配置」修改。内核目录 `backend/kernel_catalog.json` 固定可信发布地址、版本、架构及 SHA-256；当前并非任意浏览器 URL 安装器。

| 服务器架构 | 指纹内核 | 来源 |
| --- | --- | --- |
| Linux amd64 | Chromium 150.0.7871.186 | [adryfish/fingerprint-chromium](https://github.com/adryfish/fingerprint-chromium) |
| Linux arm64（包括 Apple Silicon 上的 Docker） | Chromium 153.0.8010.36 | [babelcloud/fingerprint-chromium-arm64](https://github.com/babelcloud/fingerprint-chromium-arm64)，第三方 ARM 移植 |

点「启动」后缺少的内核自动下载到服务器 `/data/kernels`，校验归档后解压并检查可执行文件；多个环境共用安装文件，各自保留独立浏览器数据目录。每个压缩包约 140 MiB，解压还需额外空间。进度、下载失败或启动失败会显示在环境列表。停止下载中的环境会取消它的后续启动；共用内核的下载可继续完成，供其他环境使用。重启服务器后已安装内核可复用，未完成的安装会重新下载。开发预览中“服务器”指本机 Docker 容器；部署到远程服务器后，访问设备只接收管理页面和浏览器画面。

设备种子随环境保存，重启不随机更换。UA/UA-CH 使用内核实际版本，避免只修改请求头而与设备 API 不一致。默认 Linux；设备系统的模拟不代表服务器真实系统改变。语言需为如 `en-US` 的语言代码，时区需为如 `America/New_York` 或 `Asia/Shanghai` 的 IANA 时区。CPU 数量是网站读取的设备参数，不会分配相应 CPU 资源。系统 Chromium 使用原生设备信息，不应用指纹内核参数。

内核、字体、图形驱动及服务器架构仍会影响可观测设备信息。更换内核可能改变指纹，浏览器数据格式也未必支持降级；有登录数据的环境应先停止并备份数据，再调整内核版本。此版本不自动升级内核。

本地 ARM64 容器已验证真实下载、重启复用，以及 UA/UA-CH、平台、语言、时区、CPU、Canvas 种子和 Xvfb 屏幕尺寸。当前无 GPU 的 Xvfb 配置中 WebGL 不可用；没有为此默认打开高 CPU 消耗的软件渲染。AMD64 包按发布方固定摘要接入，尚未在本机运行验证。

## 断网保护的实现与部署要求

绑定代理的 Chromium 运行在独立 Linux 网络命名空间中，没有可用的外网接口及默认路由。它只连接命名空间里的本地转发器，转发器通过 Unix socket 连接对应的服务端代理网关。代理网关只拨号绑定的上游代理，目的域名交给上游解析。浏览器侧的直接 TCP、DNS、UDP、QUIC、非代理 WebRTC 路径均无法直接出网。

每个环境有独立的断路状态。上游连接、认证、握手失败，或普通 HTTP 代理返回 407/502/503/504 时，会立即关闭该环境全部活动流和待建立的流，停止浏览器。保守策略下，上游返回的这些 HTTP 错误码也可能导致环境停止。正常站点关闭连接不会直接视为代理故障。

后台每 2 秒检测上游，单次网络超时为 8 秒。检测存在时间窗口，例如黑洞网络可能要等到超时才显示已中断，但期间浏览器仍无直连通道。HTTP/SOCKS4 启动检查确认传输层可达，认证和目标访问结果由实际请求验证，SOCKS5 还会预检认证。恢复后需要用户手动启动环境。

新版 Compose 为管理进程配置 `SYS_ADMIN` 和 `NET_ADMIN`，用于创建网络命名空间并启用其中的 loopback。浏览器及其转发器随后降为每个环境独有的 UID/GID（从 20000 开始持久分配），清除权限并禁止重新获取权限。数据目录和 HOME 权限为 700，X11 使用独立认证文件；旧环境在启动时迁移目录权限。远程桌面的内部 WebSocket 端口还需要每次启动生成的独立凭据，只有后端在用户授权后转发连接，不向管理客户端暴露该凭据。`/run/browser-gateways` 使用临时文件系统，重启清除旧 socket。管理数据库由 root 持有，权限 600。

未绑定上游代理的环境也使用网络命名空间，通过本地网关访问公网。网关会解析、验证并固定拨号目标 IP，拒绝 localhost、私网和保留地址，避免浏览器访问管理 API、其他环境的桌面端口及云元数据服务。若业务需要访问内网站点，当前直连模式不支持；绑定的上游代理仍按管理员指定的网络路径访问。

缺少 Linux、必要工具或隔离权限时，浏览器环境会拒绝启动。macOS 上请使用 Docker 运行完整功能。本地管理页面可以单独开发，真实浏览器依赖容器。

## 验证

在项目目录安装后端依赖及 `httpx` 后运行：

```sh
PYTHONPATH=. python -m unittest discover -s tests -v
```

`tests/test_network_namespace.py` 是需要 Linux 和上述能力的额外集成测试，在测试容器中挂载项目测试目录后，设置 `RUN_NETWORK_NAMESPACE_TESTS=1` 执行。常规测试覆盖账号和邀请、团队隔离、环境分配、标签备注、TOTP 标准向量和密钥权限、活动连接撤权、旧数据迁移、UID/X11 认证、直连网络过滤、内核安装、代理断路及 HTTP/HTTPS/SOCKS/WebSocket 转发。
